GITHUB UPDATE SETUP
===================

This program checks the latest release in a PUBLIC GitHub repository. Your
category, subcategory, location, folder-template, and history settings remain
in %APPDATA% and are preserved when the program updates.

CONFIGURED REPOSITORY
GitHub owner: m404ntfd
Repository: foldercreator
Release asset filename: ShirtFolderSetup.exe

INITIAL GITHUB RELEASE
1. The repository must be Public for the built-in updater. It does not store a
   GitHub password or personal access token.
2. You may upload the source folder to the repository for safekeeping, but the
   updater specifically reads the repository's Releases section.
3. On GitHub, choose Releases > Draft a new release.
4. For this version, create the tag v2.0.0.
5. Attach the supplied ShirtFolderSetup.exe file as the release asset.
6. Publish the release.

PROGRAM SETUP
1. Open the Shirt Design Folder Builder.
2. Choose Settings > Updates.
3. Confirm the owner is m404ntfd.
4. Confirm the repository is foldercreator.
5. Confirm the asset filename is ShirtFolderSetup.exe.
6. Leave "Check for updates automatically" selected.
7. Click Save Update Settings.
8. Click Check for Updates Now to test the connection.

PUBLISHING A FUTURE UPDATE
1. The program version inside ShirtDesignFolderBuilder.ps1 must be increased.
   Example: change 2.0.0 to 2.1.0. When ChatGPT prepares the next update for
   you, it can make this change.
2. Commit the updated files to GitHub.
3. Create and push a matching version tag, such as v2.1.0.
4. The included GitHub Actions workflow builds ShirtFolderSetup.exe and attaches
   it to the release automatically.

HOW UPDATES WORK
- At launch, the app compares its installed version to GitHub's latest release
  tag.
- If a newer release exists, it asks before downloading or installing it.
- The exact release asset filename must match Update Settings.
- After approval, the app downloads the ZIP, closes, replaces the program files,
  and starts again.
- The Check for Updates Now button performs the same check manually.

TROUBLESHOOTING
- "Not Found": confirm the owner and repository names and confirm that the
  repository is Public.
- "No asset": attach the ZIP to the release and make its filename exactly match
  the Update Settings value.
- "Tag is not a version": use a tag such as v2.1.0.
- A firewall or internet outage can prevent the check. Folder creation still
  works normally, and automatic update errors do not close the program.
